# PROMPT DE CADRAGE COMPLET DU PROJET — GeoIndexR

## 1. IDENTITÉ DU PROJET

Je souhaite développer un package R open source nommé **GeoIndexR**.

Le package doit être conçu comme un package R professionnel, robuste, documenté et potentiellement publiable sur **CRAN**.

### Nom

`GeoIndexR`

### Domaine

* Télédétection
* Géomatique
* Analyse d'images satellitaires
* Données raster
* Data Science géospatiale
* Calcul d'indices spectraux

### Objectif général

GeoIndexR doit permettre aux utilisateurs de calculer facilement, de manière fiable et reproductible, différents **indices spectraux et géospatiaux** à partir de données raster provenant notamment de satellites ou de capteurs multispectraux.

L'objectif n'est pas seulement de créer une fonction NDVI.

Le package doit fournir une **architecture générique de calcul d'indices**, permettant d'ajouter facilement de nouveaux indices au fil des versions.

---

# 2. PROBLÈME À RÉSOUDRE

Le calcul d'indices spectraux est très fréquent en télédétection.

Cependant, l'utilisateur doit souvent :

1. charger une image raster ;
2. identifier les bandes ;
3. connaître la formule de l'indice ;
4. sélectionner les bonnes bandes ;
5. effectuer le calcul ;
6. gérer les valeurs NA ;
7. conserver la projection et la résolution ;
8. sauvegarder le résultat ;
9. visualiser le résultat ;
10. répéter ces opérations pour plusieurs indices.

GeoIndexR doit simplifier ce workflow.

L'utilisateur doit pouvoir passer de :

```text
Image satellite
      ↓
Identification des bandes
      ↓
Choix de l'indice
      ↓
Calcul
      ↓
Raster résultat
```

avec un minimum de code.

---

# 6. INDICES À IMPLÉMENTER INITIALEMENT

La première version doit rester maîtrisable.

Commencer par un ensemble d'indices bien définis et correctement documentés.

## 6.1 Végétation

### NDVI

Normalized Difference Vegetation Index

Formule :

```text
NDVI = (NIR - RED) / (NIR + RED)
```

Utilisation :

* végétation
* vigueur végétative
* suivi agricole

---

### SAVI

Soil Adjusted Vegetation Index

```text
SAVI = ((NIR - RED) / (NIR + RED + L)) × (1 + L)
```

Le paramètre `L` doit être configurable.

Par défaut :

```r
L = 0.5
```

---

### EVI

Enhanced Vegetation Index

```text
EVI = G × (NIR - RED) /
      (NIR + C1 × RED - C2 × BLUE + L)
```

Les paramètres doivent être configurables.

Valeurs par défaut classiques :

```text
G  = 2.5
C1 = 6
C2 = 7.5
L  = 1
```

---

### GNDVI

```text
GNDVI = (NIR - GREEN) / (NIR + GREEN)
```

---

## 6.2 Eau

### NDWI

```text
NDWI = (GREEN - NIR) / (GREEN + NIR)
```

Documenter clairement la définition utilisée.

Le package doit éviter toute ambiguïté entre les différentes variantes d'indices portant le même acronyme.

---

### MNDWI

Modified Normalized Difference Water Index

```text
MNDWI = (GREEN - SWIR) / (GREEN + SWIR)
```

---

## 6.3 Urbanisation

### NDBI

Normalized Difference Built-up Index

```text
NDBI = (SWIR - NIR) / (SWIR + NIR)
```

---

## 6.4 Sols

### BSI

Bare Soil Index

Implémenter la formule choisie et la documenter précisément.

---

## 6.5 Humidité

### NDMI

Normalized Difference Moisture Index

```text
NDMI = (NIR - SWIR) / (NIR + SWIR)
```

# 16. VALEURS DE RÉFLECTANCE

Le package doit fonctionner avec des valeurs de réflectance.

Documenter clairement la question du scaling.

Certaines images satellites sont stockées sous forme :

```text
0 – 10000
```

alors que la réflectance peut être :

```text
0 – 1
```

Le package doit expliquer que les indices normalisés comme NDVI sont généralement invariants à un facteur multiplicatif commun, mais que les indices comportant des constantes additives, comme EVI/SAVI, peuvent nécessiter une attention particulière.

Ne jamais appliquer automatiquement un scaling sans que le comportement soit explicite et documenté.

Pendant le développement :

1. Ne pas écrire de code inutile.
2. Ne pas créer une fonction uniquement pour quelques lignes si elle n'apporte aucune valeur.
3. Ne pas multiplier les dépendances.

5. Tester chaque fonctionnalité.
6. Documenter chaque fonction publique.

# 46. CRITÈRES DE RÉUSSITE

Le projet sera considéré comme réussi lorsque l'utilisateur pourra faire :

```r
library(GeoIndexR)

image <- terra::rast("multispectral.tif")

ndvi <- geo_index(
    image,
    "NDVI"
)
```

et obtenir immédiatement un `SpatRaster` correctement géoréférencé.

Il devra également pouvoir faire :

```r
indices <- geo_indices(
    image,
    c("NDVI", "NDWI", "NDBI")
)
```

et obtenir un raster multibande.

Enfin :

```r
index_registry()
```

doit permettre de découvrir les indices disponibles.
